      CLI commands

      Eight commands cover the whole lifecycle. Use them standalone as sf-lwc <command> (or npx sf-lwc), or natively inside Salesforce CLI as sf lwc <command>.

      sf-lwc init

      Writes the default registry spec and workspace settings to sf-lwc.json so team installs run consistently.

      $sf-lwc init

      sf-lwc add [source] [component...]

      Installs components and resolves sub-dependencies (child LWCs, Apex controllers, labels), updating sf-lwc.lock.json. Omit component names to launch interactive multi-select.

      $sf-lwc add svierk/awesome-lwc-collection

      sf-lwc list [source]

      Lists available components from a remote GitHub repository or local SFDX project without touching GitHub REST API quota. (Alias: ls)

      $sf-lwc list

      sf-lwc diff <component>

      Displays a unified, line-by-line colored diff between your local customized copy and the upstream registry version.

      $sf-lwc diff dataTable

      sf-lwc update [component...]

      Compares lockfile versions with upstream registry, then safely upgrades component files and Custom Labels (use --all to upgrade all).

      $sf-lwc update --all

      sf-lwc remove <component...>

      Safely removes an installed component and its files, checking dependency trees to prevent breaking dependent components (override with --force). (Alias: rm)

      $sf-lwc remove dataTable

      sf-lwc doctor

      Checks SFDX project root, configuration, registry reachability, lockfile integrity, and verifies that every tracked file exists on disk.

      $sf-lwc doctor

      sf-lwc pack <component>

      Inspects metadata dependencies through the Salesforce Tooling API across Apex, Labels, and child LWCs, exporting into clean .sf-lwc/ sidecars. (Alias: export)

      $sf-lwc pack myComponent -o myOrg

      Project Architecture & Internals

      A reference for contributors on how sf-lwc works under the hood—from zero-quota transport streaming to recursive dependency resolution and atomic DX file installs.

      Execution Lifecycle

      When a user runs sf-lwc add or sf lwc add, the engine processes four distinct architectural stages:

      01

      Transport & Zero-Rate-Limit Cache

      src/source.js

      Resolves the target repository specification (owner/repo[@ref], git URLs, or local directory paths) with zero unauthenticated REST API quota consumption.

      • Codeload Snapshot Streaming: Unauthenticated GitHub requests stream gzip tarballs from codeload.github.com/{owner}/{repo}/tar.gz/{ref} and parse archives in-memory via parseTar() into a virtual file tree (_filesMap). api.github.com is never contacted, keeping the user's 60 req/hr IP quota completely untouched.
      • Native Git Clone Fallback: If codeload download fails (e.g., enterprise proxies), falls back to git clone --depth 1 over standard Git HTTPS protocol.
      • Local Source Inspection: Scans local directories for sfdx-project.json and indexes components directly from package directories.
      02

      Resolution & Manifest Engine

      src/resolve.js

      Locates component manifests, normalizes names, and recursively traverses the dependency graph.

      • Manifest Discovery: Looks for explicit frozen manifests in .sf-lwc/<name>.json sidecars or synthesizes bundle manifests dynamically from standard SFDX directory layouts (force-app/main/default/lwc/<name>).
      • Security & Path Traversal Guard: The validate() and safePath() assertions enforce semantic version formatting, API versioning, and strictly disallow backslashes, leading slashes, and directory escaping (..).
      • Graph Resolution & Cycle Detection: Recursively walks child dependencies, detects cyclic dependencies, and produces an ordered installation queue.
      • Name & Case Normalization: Matches component identifiers across exact, case-insensitive, kebab-case (toKebabCase), and stripped formats via matchComponentName.
      03

      DX Installation & Non-Destructive Merging

      src/install.js · src/labels.js

      Coordinates filesystem writes and integrates metadata into the destination Salesforce DX project.

      • Project Route Discovery: Inspects sfdx-project.json in the workspace to identify the target package directory (defaults to force-app/main/default).
      • File Distribution: Writes LWC bundles to lwc/<name>/ and Apex classes/tests to classes/.
      • Custom Labels Merger (src/labels.js): Non-destructively parses CustomLabels.labels-meta.xml, detects existing <fullName> entries, and appends missing labels before </CustomLabels> without overwriting existing labels or comments.
      • Atomic Lockfile Persistence: Updates sf-lwc.lock.json with installed component names, versions, and every written file path for clean drift detection and audits.
      04

      Dependency-Aware Lifecycle & Removal

      src/remove.js · src/update.js · src/doctor.js

      Protects project integrity during updates, diagnostics, and component removals.

      • Graph-Aware Removal: src/remove.js consults lockfile dependencies using findBlockingDependents(). If component A depends on component B, removing B is blocked with a descriptive error unless --force is provided.
      • Lockfile Sync: Deleting the last installed component cleans up sf-lwc.lock.json cleanly.
      • Diagnostics Suite (src/doctor.js): Verifies sfdx-project.json health, configuration validity, registry connectivity, and verifies that every file recorded in the lockfile exists on disk.

      Org Dependency Tracing & Packaging

      Automated Metadata Extraction

      src/pack.js

      The sf-lwc pack <component> command connects to your active Salesforce Org or local SFDX workspace to reverse-engineer and export components with their full dependency graph.

      • Static AST & Regex Analysis: Scans LWC templates for child component tags (<c-...>), JavaScript for Apex imports (@salesforce/apex/...), and custom labels (@salesforce/label/c....).
      • Tooling API & Local Matching: Resolves corresponding Apex classes (.cls and .cls-meta.xml), unit test classes, and custom label XML definitions.
      • Sidecar Generation: Emits a self-contained .sf-lwc/<name>.json sidecar with exact versions, dependencies, and file listings ready for distribution.

      Codebase Anatomy

      Core module breakdown for contributors navigating the repository:

      Module / Path Responsibility & Core Exports
      bin/sf-lwc.js CLI entry point, argument parsing via util.parseArgs, interactive multi-select UI (@clack/prompts), and TTY formatting.
      src/source.js Source abstractions: createSource(), Codeload archive streaming (fetchTarball, parseTar), native Git clone fallback, local SFDX discovery.
      src/resolve.js Manifest schema validation (validate), path traversal security guards (safePath), recursive dependency tree resolution, name normalization.
      src/install.js File copy pipeline, target package directory routing (sfdx-project.json), lockfile reading and atomic writing (readLock, LOCK_FILE).
      src/labels.js CustomLabels XML parsing and non-destructive merging (mergeCustomLabels).
      src/remove.js Dependency-graph safety checks (findBlockingDependents), file removal, and lockfile synchronization.
      src/diff.js Unified line-by-line colored diff comparing local component files against registry versions.
      src/doctor.js Salesforce DX workspace diagnostics, registry reachability testing, and lockfile file existence verification.
      src/pack.js Tooling API metadata dependency tracer (Apex classes, tests, labels) and .sf-lwc/ sidecar exporter.
      packages/plugin-lwc Native Salesforce CLI (sf) plugin integration powered by @oclif/core and @salesforce/sf-plugins-core.
